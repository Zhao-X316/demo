# 教辅前端简化方案

日期：2026-09-07。状态：设计提案，尚未实施。

基线：`codex/t2-artifacts`，`1bf9407`。依据当前代码、独立演示桌面窗口和项目《傻瓜式一站式产品设计核心_v1》。本方案默认优先优化“上传后批改”，同时容纳背诵、找题和查看学生学习情况。

## 1. 推荐方向

将一级导航收敛为 **工作台 / 资料 / 学生**，设置放在底部。默认进入工作台，用“新建批改”和可继续处理的任务列表组织日常工作。

一次任务沿着 **资料 → 系统处理 → 老师核对 → 结果** 走完。作业、背诵和题型成为任务内部的选项；老师进入核对时，系统根据当前任务打开适合的核对界面。

保留现有能力，但调整出现的时机。首先让老师看到要做的事，其次是完成这件事所需的证据，最后才是历史、版本和高级配置。

## 2. 当前复杂在哪里

| 当前事实 | 对使用者的负担 | 简化办法 |
| --- | --- | --- |
| 应用先分背诵、改作业、错题与掌握；背诵下有 7 个导航项，改作业下有 5 个 | 同一班级的工作分散在多套入口；切换模块又回到概览 | 固定三项主导航，任务列表聚合进度，班级上下文保留 |
| 题目批改页再分上传、客观题、主观题、默写、补录、题库、知识点 7 个标签 | 老师需要先理解系统分类，才能找到下一步 | 由任务直接进入对应核对，补录在当前任务“更多”中 |
| 首页同时展示 5 个统计卡、待办、统计口径、掌握快照和教学行动等 | 空数据和解释文字也占据首屏，常用动作不突出 | 首屏只放主要动作和待办；统计、掌握情况移到“学生” |
| 题库默认打开导入，另外有查重、候选、版本影响和蓝图组卷模式 | 进入资料区域先面对管理流程 | 默认展示已有资料；导入、整理、更新影响成为就地动作 |
| 部分页面各自选择班级和学生；顶栏“搜索 / 跳转 ⌘K”尚无处理逻辑 | 重复选择，以及看起来可用却没有反馈的控件 | 导航记住上下文；先移除无行为入口，资料区保留真实搜索 |

当前上传表单已有分步结构和可折叠的补充项，可直接复用。主要改动在应用入口、页面信息顺序以及任务间的衔接。

## 3. 新的信息结构

```text
工作台（默认）
  新建批改 → 作业 / 背诵 → 选择内容与材料
  待我处理 / 处理中 / 已完成
  当前任务 → 资料、处理状态、老师核对、结果

资料
  题目 / 背诵内容 → 列表、搜索、详情
  导入资料、整理待确认项、组一份练习
  详情中的更多 → 知识点、版本、更新影响

学生
  班级概览 → 学生列表 → 学生详情
  学生详情 → 作业记录 / 错题 / 学习情况
  班级学习情况 → 掌握快照、教学重点、相关导出

底部：设置
```

“待我处理 / 处理中 / 已完成”是任务列表筛选，不增加一套侧栏导航。“资料”的题目与背诵内容采用页内切换。进入任务后，以当前任务的班级、作业和学生为准。

选择三项入口，是为了让资料整理、班级管理这两类独立工作仍有稳定位置。全部塞进工作台会再次形成长页面。

## 4. 三个关键页面怎么改

### 工作台：一个主要按钮，一份任务列表

- 顶部只保留当前班级和“新建批改”。不展示五个统计卡，也不常驻口径说明。
- 每行显示任务名称、班级、简短进度和一个下一步动作。例如“历史随堂练习 · 1 处待核对 → 继续核对”，或“第 2 页缺失 → 补充材料”。
- 阻断处理的问题排在普通确认前面；无待办时给出清楚的空状态和新建入口，不制造空统计。
- 历史工作从“已完成”找到，处理中任务留在同一列表。后台失败须显示具体原因和可执行动作。
- 选中任务再展示详情，默认不将所有任务的证据和操作同时铺开。

### 批改详情：保持任务上下文，集中处理例外

1. **资料**：班级和最近内容可沿用；老师确认本次作业或背诵内容，再放入材料。按已有支持范围选择图片、PDF 或录音。材料类型只能在可靠时自动识别，有歧义时就地询问。首次没有班级、内容、模板或可用答案时，明确引导补齐实际必需项。
2. **系统处理**：沿用当前领域处理流程，在任务内显示进度、重复或跳过数量、失败原因。“处理中”不能与“已评分”混用。
3. **老师核对**：分“需要判断 / 待确认 / 暂时无法处理”。先处理错人风险、缺页等阻断项；每次聚焦一个判断，旁边保留原文或录音证据、评分依据、AI 建议和老师最终决定。可展开全部项目，不能把正常项永久藏起来。
4. **结果**：清楚区分“老师已确认”和“已发布”。未完成核对时说明阻断项；发布前明确本次对象、份数和影响，单独确认发布。

这四段是进度与内容组织，不是禁止返回的强制向导。返回补材料、切到下一位学生后，应保留本次任务、当前项目和筛选状态。

批量操作严格使用现有领域能力：客观题、默写只对满足条件的项目调用既有严格批量确认；主观题保留逐项或逐评分点核对，不在界面里假设已经存在通用批量通过能力。背诵确认如会影响排程，仍明确展示影响并由老师确认。

### 资料与学生：在相关对象旁边放动作

| 页面 | 默认可见 | 按需展开 |
| --- | --- | --- |
| 资料列表 | 搜索、题目或背诵内容、待整理提示、导入入口 | 查重处理、评分依据、知识点链接、版本和更新影响 |
| 资料详情 | 内容、答案或评分依据、使用状态 | 历史版本、影响中的作业、未来默认版本设置 |
| 学生列表 | 班级、学生、与当前作业相关的处理情况 | 名册管理、班级学习情况 |
| 学生详情 | 作业记录、错题和本次可用学习证据 | 完整轨迹、快照范围、历史比较 |
| 班级学习情况 | 核心结论、证据日期与覆盖情况 | 统计口径、快照生成、教学重点、导出 |

更新答案或评分依据时，必须继续区分“以后使用新版”和“重新处理历史作业”。知识点、版本等业务概念在需要作出决定的位置保留，内部 ID、哈希和技术日志放进详情。

快照的日期、范围、证据不足或已过期状态不能折叠掉；学生的临时教学支持状态不能展示成固定能力标签。

## 5. 交互与视觉约定

- 延续当前紫色强调色和中性工具界面。用减少内容与分层改善密度，保持清楚的字号和足够大的点击区域。
- 每页只突出一个主要动作。重复的“去某模块”按钮，尽量改成带上下文的具体动作，如“核对这道题”。
- 错误在当前操作旁显示，并给出下一步。上传重复、已跳过、处理失败和保存成功都有明确反馈。
- 默认只展开完成当前步骤所需字段；高级设置折叠。缺页、身份风险、未保存修改和失效证据等关键提示始终可见。
- 班级筛选可以记住上次选择，但不能改变已创建任务绑定的班级和作业。切换全局班级不能把进行中的任务重新归属。
- 新建、返回、关闭、刷新后恢复的行为应一致；未保存修改要有清楚处理方式。

## 6. 实施顺序与代码边界

| 顺序 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 第一批：先简化入口 | 固定三项导航、工作台首屏、旧功能归位、移除空入口；沿用现有业务组件 | 所有旧功能可达；首页能直接新建或继续任务；班级上下文正确 |
| 第二批：串起批改闭环 | 增加任务详情壳，接入现有上传、处理与核对控制器；明确任务定位和恢复方式 | 不跨模块找复核；返回不丢任务；失败和重启可恢复；原有确认与发布边界保留 |
| 第三批：压缩次要页面 | 资料默认列表、详情就地整理；学生页收纳统计、错题与掌握情况 | 常用内容少跳转；高级能力可找到；快照与历史版本提示正确 |

**第一批开始前先验证任务列表的数据来源。** 如果现有读取接口不能可靠列出跨模块任务、待处理数或恢复位置，就补充只读摘要接口，再接工作台。不能依靠前端内存凭空提供“历史任务”和“重启继续”。后两批可复用这份摘要，不再维护第二份业务状态。

建议在现有模块边界上增加轻量应用壳：

- `src/App.tsx`：导航与页面上下文。
- 拟新增 `src/pages/workspace/`：工作台列表、任务详情壳，以及调用现有领域读取接口的适配器。
- 任务描述使用带领域标识的联合类型，保存原领域任务或批次 ID，以及可恢复定位；标题、状态和下一步动作由原事实推导。
- 上传和复核继续复用 `src/pages/exam/` 中的控制器、面板及 API；背诵继续使用原领域流程。
- `QuestionBank`、`LearningInsights`、`ClassDashboard` 的现有组件按新入口组合，业务行为保持可追踪。
- 跨模块任务摘要只读聚合，不建立复制所有模块状态的万能任务表。确认评分、发布、变更排程、更新版本等写操作仍调用原领域命令和事务。

## 7. 验收标准

### 界面与流程

1. 主导航固定三项，设置作为底部工具；首页一个主按钮，没有大块常驻统计口径。
2. 已具备班级、作业和所需模板或答案的高频场景，从进入到开始处理，目标不超过三个必要决定；首次建档和缺材料另行记录，不能为了达标隐藏必需信息。
3. 未完成任务可从工作台一次进入正确位置；一次核对无需先去选择客观题、主观题或默写模块。
4. 每个异常明确回答“哪里有问题、依据是什么、我接下来做什么”；处理后不丢任务范围和当前定位。
5. 在 1280×800 与 980×680 桌面窗口下，无横向溢出，首屏看得见主要动作；必要内容可纵向访问。示意图另需适配对话窄屏。

### 正确性与效果

6. 确认评分与发布保持独立；不能静默错学生、错任务、错页或重复发布。背诵排程、历史成绩和答案版本副作用沿用既有保护。
7. 对每个受影响领域验证继续任务、切换班级、失败重试、返回和重启恢复。回归沿用项目现有检查；涉及 Tauri 时单独运行外壳检查，不能只依赖 `cargo test --workspace`。
8. 用相同任务比较首次行动、回退次数、异常漏看和老师主动操作时间。真实试点具备条件后，按既有 R5 规范比较每 50 份提交的主动操作分钟数；菜单减少或演示图通过均不能替代真实教师效果证据。

## 8. 本次交付范围

交付本设计文档及可切换的界面示意。示意使用虚构材料和学生，所有操作只改变展示状态，未接业务接口；可以体验工作台、资料、学生以及核对后独立发布的组织方式。

应用源代码和已推送的重构提交未因本提案改变。本次未执行实现阶段的应用回归，也不声称 R5 真实教师验收通过。

示意检查：HTML 片段约束和 JavaScript 语法通过；浏览器已验证三个主入口、新建到处理结果、单题确认后仍待发布、独立发布确认。已查看桌面及内容宽约 320px 的窄屏排版，未见横向溢出；这些仅验证示意交互。
