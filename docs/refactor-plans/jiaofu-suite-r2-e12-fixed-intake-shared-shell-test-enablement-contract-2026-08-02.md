# R2-E12 `FixedIntakeTab` 共享上传壳测试前置执行合同

## 目标

在不修改生产代码的前提下，为 `src/pages/Exam.tsx` 剩余固定上传共享流程建立浏览器特征保护。先冻结“老师按拍摄顺序选照片 → 自动判断每人页数 → 确认材料类型 → 选择起始学号和缺交学生 → 查看联系表并扣住重拍页 → 进入对应终审”的现有行为，再另开合同选择单一生产外移边界。

## 候选边界取证

1. 当前 `FixedIntakeTab` 为第 307～1837 行，共 1,531 行；它不是可直接整体搬走的单一展示组件。
2. 共享流程持有班级/作业、学生文件、答案资料、页数周期、材料类型、归组起点/缺交、联系表、质量确认、重拍和结果路由；三材料处理还分别持有普通卷分析、答题卡模板/处理、默写模板/处理状态。
3. 共享流程现有十一类业务调用：页数周期推断、批次准备、材料类型确认、归组确认、归组证据读取、质量确认、重拍替换，以及答案资料分析、一致确认、沿用当前答案、另存答案新版本。
4. 普通卷“结构确认 → 私有题库旁路 → 客观题识别”已有 `scripts/test_ordinary_question_sync_ui.py`；本批不重复改写该测试，只验证共享流程把合格普通卷送到标准卷终审。
5. 答题卡和默写的模板识别、确认、逐页处理与失败重试仍是各自独立候选；本批只用真实 DTO 形状固定其处理结果对终审路由的影响，不宣称模板内部已完整覆盖。
6. 父级继续持有顶层 Tab、workbench 加载、全局错误/成功提示与统一 `onOpenReview → load()`；老师补录、题库、知识点和已外移终审 Tab 不属于候选。

## 必须冻结的当前行为

1. 没有已确认作业版本时显示保守空态，不允许临时拼出题目或答案，也不显示上传/终审动作。
2. 学生卷只接受 JPG/JPEG/PDF；选择顺序原样传给后端。界面展示前四个文件和剩余数量，页数周期建议可由老师修改，提交仍使用当前确认值。
3. 批次准备请求必须绑定固定作业版本、按选择顺序排列的全部文件、可选答案文件或去除首尾空白的粘贴答案、每人页数、`materialType=auto` 和幂等键；首次失败后重试复用同一幂等键并保留输入。
4. 答案资料仅作候选：整理失败可重试；完全一致仍需老师一次确认；冲突可沿用当前已确认答案，或在评分点对应关系完整且不复用同一旧点时另存未来新版本；当前批次不被静默重写。
5. 材料类型不确定时只让老师在普通试卷、答题卡、默写中确认一次；失败保留三个选项和当前批次，成功后才进入学生归组。
6. 归组默认按学号升序连续映射。老师可选择第一份学生并标出其后的缺交学生；确认请求必须准确携带起始学号和缺交学号，失败保留选择供重试。
7. 归组确认后只读取当前批次联系表；老师可逐页标记需重拍。质量确认请求必须准确携带所有拒绝页，失败保留标记供重试。
8. 质量确认不生成分数或发布；被扣住页面保留学生/页码定位并允许选择一张 JPG/JPEG 重拍替换，替换后重新读取联系表。
9. 结果区继续显示可批量确认、需复核、受阻、原因和唯一下一步。受阻、材料未确认、归组未确认或质量未确认时不得进入终审。
10. 普通卷和无主观区答题卡进入“标准卷终审”；有主观区答题卡进入“答题卡主观题”；默写进入“默写复核”。路由只切换工作台，不自动确认、计分或发布。
11. 全过程不得触发老师补录、题库手工录入、知识点写入、终审确认、成绩发布或学习证据写命令。
