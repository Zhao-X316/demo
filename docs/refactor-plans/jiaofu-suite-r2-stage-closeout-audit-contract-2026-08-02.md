## 3. 允许修改

本批只允许修改：

1. 本审计合同；
2. R2 阶段收口验收回执；
3. 重构实施与验收标准、项目文档索引、任务地图；
4. 修改记录队列及其索引。

禁止修改生产代码、测试代码、依赖、Rust/SQL/DTO、CSS、构建配置和历史验收回执。

## 4. 必须逐项成立的收口条件

### 4.1 顶层职责

1. `Exam.tsx` 只负责基础列表/workbench 加载、统一成功/错误提示、刷新、终审 Tab 切换和七个完整 Tab 的顶层编排；
2. 七个完整 Tab 均位于独立模块：`KnowledgeTab`、`QuestionTab`、`GradeTab`、`ObjectiveReviewTab`、`DictationReviewTab`、`SubjectiveReviewTab`、`FixedIntakeTab`；
3. `Exam.tsx` 不再定义这些 Tab，不直接持有固定上传写调用、Tauri 文件选择器或十三个子面板。

### 4.2 依赖所有权

1. 本地依赖只允许从父页流向 Tab、再流向子面板/共享纯依赖；
2. 不得存在本地循环引用；
3. 十三个封闭子面板只能由所属 feature 消费；
4. 共享 `TYPE_LABEL` 与 `examPure` 保持单向消费，不形成新的页面级事实源。

### 4.3 合同、回执与行为保护

1. 七个完整 Tab、十三个子面板和一个共享依赖的生产外移均须有独立合同和对应验收回执；
2. R2 特征保护合同必须覆盖七个 Tab、主观题五个子面板和固定上传共享壳；
3. 当前十三个浏览器脚本须覆盖上述入口及普通试卷题目沉淀侧路；
4. 历史机械外移证据只按已归档回执确认，不伪称本批重新生成全部历史逐字节候选。

### 4.4 行为与工程门禁

必须全部通过：

1. `npx tsc --noEmit`；
2. `node --test` 的纯函数直接测试 6/6；
3. `npm run build`；
4. 十三个 UI 脚本 `py_compile`；
5. 十三个浏览器回归脚本；
6. `git diff --check`；
7. HEAD、Git index SHA-256 与 staged 保持不变；
8. 本批生产代码 diff 必须为空，新增路径只能属于本合同和允许的记录文件。

## 5. 判定规则

- 任一项缺失：R2 保持“阶段收口审计待完成”，不得进入 R3；
- 全部成立：R2 可标记为“前端 feature/Tab 结构拆分阶段完成（本地自动化，未集成、未发布）”；
- 无论结论如何，R3 reducer/hook/request 编排都必须另建迁移表、并发/刷新/失败恢复测试和独立设计合同，不能在本批直接改写。

## 6. 明确不证明

本审计不证明真实 OCR、OMR、手写识别、学生/页面归属、机器评分、provider 稳定性、调用成本、独立 `.app`、真实老师减负、商业化可用性、集成或发布状态。
