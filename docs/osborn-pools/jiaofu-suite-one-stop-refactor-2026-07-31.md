# 想法池：教辅系统一站式体验与可持续重构

## P1 自由发散（27 个）

1. 把老师每次工作抽象为一个可恢复的“任务会话”，从导入、识别、异常处理、终审到发布都围绕同一个会话推进，页面不再要求老师理解底层模块。 `[P1]`
2. 首页只展示“今天要完成的事、卡在哪里、下一步做什么”，背诵、批改、题库和图谱作为任务能力而不是并列的软件子系统。 `[P1]`
3. 建立全系统异常收件箱，页面质量、学生归组、OCR、评分分歧、知识链接和发布阻断都使用统一的异常卡协议。 `[P1]`
4. 为普通试卷、答题卡、默写和背诵分别定义“正常直通路径”，正常材料自动前进，只有异常才打断老师。 `[P1]`
5. 把照片文件名自然排序、冻结后的 `import_index`、页面周期和学生绑定做成统一导入清单，所有后续重试只读清单而不重新猜序。 `[P1]`
6. 上传前提供胶片式顺序预览，只允许拖动纠正或删除明显误传；一旦确认即冻结顺序并形成审计 revision。 `[P1]`
7. 建立“本次批改进度”统一读模型，直接回答已收到多少、已归组多少、可自动确认多少、需人工多少、被阻断多少。 `[P1]`
8. 每个老师任务只保留一个主按钮，按钮文案根据当前状态变化为“开始识别”“处理 3 个异常”“确认并发布”等可执行动作。 `[P1]`
9. 把高级模板、模型、阈值、版本和知识链接设置放入渐进披露区，默认流程只索取班级、材料和答案三类必要输入。 `[P1]`
10. 为陌生材料建立“机器先生成候选、老师一次确认结构、以后自动复用”的首用合同，避免每次都重新配置模板。 `[P1]`
11. 前端按业务能力建立 `features/exam-intake`、`features/objective-review`、`features/subjective-review`、`features/dictation-review` 等包，每个包自带组件、hook、类型和测试。 `[P1]`
12. 页面文件只负责路由、标签和跨能力协调，不再直接保存几十个业务字段或执行具体 IPC 编排。 `[P1]`
13. 把页面中的纯解析函数和标签映射移到领域适配器，保证它们可单测且不会在 React 重渲染路径中重复定义业务语义。 `[P1]`
14. 用按任务划分的 reducer 或显式状态机替代大量相互关联的 `useState`，把“不可能状态”从 UI 层消除。 `[P1]`
15. 给每个 feature 建立单一查询 hook 和单一命令 hook，集中处理 busy、error、toast、刷新和幂等请求键。 `[P1]`
16. 把 `src/api/exam.ts`、`src/api/knowledge.ts` 按用例拆成小型客户端模块，同时保留兼容导出层，避免一次性改写全部调用方。 `[P1]`
17. Tauri command 只做参数反序列化、权限/路径边界和错误映射，业务事务全部下沉到 crate 的 use-case service。 `[P1]`
18. Rust 大服务按“查询、计划、确认、发布、未来版本升级”拆为内部子模块，对外仍由原 `service` facade 暴露稳定函数。 `[P1]`
19. 把业务文件中的超长测试模块迁入同目录独立 `*_tests.rs`，生产逻辑和测试夹具分别可读，同时保持私有函数可通过 `#[cfg(test)] mod tests` 使用。 `[P1]`
20. 为跨模块写操作定义统一的 use-case receipt，冻结输入 hash、影响对象、事务结果、audit/outbox ID 和可重试状态。 `[P1]`
21. 把 `learning_evidence`、题目版本、评分 revision、发布 revision 的跨模块引用做成共享契约类型，禁止前端自行拼接语义。 `[P1]`
22. 建立统一证据抽屉组件，可从背诵、客观题、填空、简答和图谱节点回到原音频/原图、机器建议和老师决定。 `[P1]`
23. 把 AI 任务拆为可缓存的原子阶段：材料分类、页面结构、OCR/ASR、答案对齐、评分建议、知识链接；修改下游规则不重复调用上游模型。 `[P1]`
24. 为每个 AI 阶段保存输入 hash、模型/规则版本、输出校验和失败原因，界面只把“下一步可做什么”展示给老师。 `[P1]`
25. 建立重构前特征测试：用现有隔离 fixture 固定关键 DTO、数据库状态、重启回读和失败恢复，再进行纯移动式拆分。 `[P1]`
26. 在 CI 中增加文件规模和职责预算报告：只对持续增长或新增超大文件告警，不以单一行数作为否决。 `[P1]`
27. 把真实减负指标直接接入任务会话：老师主动操作次数、异常复核数、完整听音/看卷比例和每百份耗时，与功能正确性分开验收。 `[P1]`

## P2a SCAMPER 补盲（19 个）

### S — Substitute 替代

28. 用“任务步骤条 + 当前唯一动作”替代 `Exam.tsx` 顶部七个平级标签，让老师不需要判断该去哪个技术页面。 `[P2a-S]`
29. 用领域 reducer/状态机替代入口页几十个相互关联的布尔状态，状态迁移同时产出可测试的 next action。 `[P2a-S]`
30. 用按能力注册的 command router 替代持续增长的单体 Tauri command 文件，注册表仍保持一个 IPC 名称真相源。 `[P2a-S]`

### C — Combine 合并

31. 合并 M3 错题事实与 M6 掌握推断的老师入口，默认展示“哪里需要巩固”，抽屉内再区分事实、推断和证据可信度。 `[P2a-C]`
32. 合并普通卷、答题卡、默写的采集外壳，复用文件顺序、学生范围、缺交、重复和缺页处理，识别管线在冻结清单后分流。 `[P2a-C]`
33. 合并题面来源与答案来源的首用向导，老师一次上传空白卷/题目文件和答案资料，后台分别生成不可变候选。 `[P2a-C]`

### A — Adapt 借用

34. 借用相册导入体验，把照片显示成按时间/文件名排序的胶片，异常页像“缺口”一样插在学生页组之间。 `[P2a-A]`
35. 借用邮件收件箱的“聚类 + 批量处理 + 例外保留”模式，让相同客观答案和相同填空写法可成组确认。 `[P2a-A]`
36. 借用航空值机的“总览一次确认、局部异常单独处理”模式：人数和页数吻合时不逐生确认，异常点之后不静默平移。 `[P2a-A]`

### M — Modify 改造

37. 把当前按模块显示的进度改造成按老师目标显示，例如“这批 40 人还差 2 份确认”，不展示数据库状态名。 `[P2a-M]`
38. 把错误提示改造成可执行异常卡，必须包含证据、影响范围、一个主修复动作和保留人工补录入口。 `[P2a-M]`
39. 把知识链接复核从独立维护任务改造成批改中的轻量建议，仅在题目达到 L2 且老师选择用于图谱时出现。 `[P2a-M]`

### P — Put to another use 转用

40. 把既有 audit/outbox 不只用于审计，也用于构建任务时间线、失败恢复入口和诊断包索引。 `[P2a-P]`
41. 把 K1 的稳定知识节点同时作为背诵评分点、题目评分点、错题巩固和班级仪表盘的坐标，减少同义标签副本。 `[P2a-P]`

### E — Eliminate 消除

42. 消除 `Exam.tsx` 内已被题库页覆盖的手工题目/知识点管理标签，仅保留上下文跳转或兼容入口。 `[P2a-E]`
43. 消除页面各组件重复实现的 loading/error/toast/refresh 样板，统一到 use-case hook 与通知层。 `[P2a-E]`
44. 消除为了重新评分而重复 OCR/ASR 的路径，让上游成功结果按 hash 和版本复用。 `[P2a-E]`

### R — Reverse / Rearrange 反转或重排

45. 反转“先维护题库再批改”的顺序：批改时自动精确复用或沉淀私有候选，老师只处理影响当前批改的缺口。 `[P2a-R]`
46. 反转“先拆文件再补测试”的顺序：先用现有老师任务生成验收回执，再按回执边界逐个抽取模块。 `[P2a-R]`

## P2b 利益相关方视角轮换（14 个）

### 老师视角

47. 首次打开直接提供一套可删的示例班级和示例任务，让老师在三分钟内体验完整流程，不要求先理解系统结构。 `[P2b-用户]`
48. 允许老师把未完成任务安全退出，重开后精确回到“第 3 个异常待判断”，而不是重新导入或重新识别。 `[P2b-用户]`
49. 发布前只呈现会影响学生结果的最终核对项，知识库沉淀、统计和图谱生成在后台完成或另行提示。 `[P2b-用户]`
50. 所有自动化都保留“我来补录”入口，并明确补录改变的是当前作答、未来答案版本还是知识链接，防止老师误改历史。 `[P2b-用户]`

### 实施者视角

51. 为每个 feature 定义公开 facade 和禁止跨层导入规则，页面只能依赖 facade，不能直接引用别的 feature 内部组件。 `[P2b-实施者]`
52. 给超大 Rust 服务先建立调用图和事务边界表，再按用例拆文件，避免把一个事务拆成跨模块多次提交。 `[P2b-实施者]`
53. 把 DB 查询 SQL 与业务状态迁移分开：查询读模型可独立优化，写模型继续保持事务和保护触发器。 `[P2b-实施者]`
54. 把现有大文件重构拆成“测试外移、纯函数外移、组件外移、状态编排外移”四批，每批只改变一种结构因素。 `[P2b-实施者]`

### 竞争者视角

55. 假设竞争产品拥有更强模型，仍通过本地证据链、老师终审、可逆版本和跨模块知识坐标形成不依赖模型品牌的优势。 `[P2b-竞争者]`
56. 把“异常处理速度”和“首次成功完成率”作为核心产品指标，而不是只宣传 OCR/AI 准确率。 `[P2b-竞争者]`
57. 提供可替换 provider 的标准任务协议和成本账本，使模型价格或政策变化时不需要重构老师工作流。 `[P2b-竞争者]`

### 极端与边缘视角

58. 在完全断网时仍允许导入、归组、查看原图、人工补录和发布确定性客观结果，需要云模型的步骤进入可恢复队列。 `[P2b-边缘]`
59. 在 40 人 × 多页材料中间缺一页时，系统只冻结异常点附近绑定，不允许后续 39 人整体错位。 `[P2b-边缘]`
60. 在订阅到期、provider 故障或模型停用时，历史数据、证据、导出、备份恢复和人工工作流继续可用，只阻止新的托管 AI 消耗。 `[P2b-边缘]`
