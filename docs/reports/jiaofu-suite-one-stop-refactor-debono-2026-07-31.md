# 价值回溯：教辅系统一站式体验与可持续重构

## 最强存活论证

### 命题一：重构值得继续，价值核心是可重复的安全施工方法

通过 **S2 条件缩窄法**，原先覆盖前端、Rust 服务和一站式任务壳的广义重构，缩窄为当前唯一成立区间：R1-A 测试模块外移。它能把约 1060 行测试从生产服务文件中分离，同时保持生产逻辑、公开符号、SQL、事务与界面不变。更重要的产物是“唯一合同 → 单因素改动 → 同批回执 → 独立复审”的施工模板，后续每一批都能复用。

### 命题二：一站式体验仍是正确的产品假设

通过 **S1 逆向利益相关方**，老师真正需要的是“当前任务做到哪、还剩什么、下一步按哪个按钮”，实施者需要领域事实、事务和版本继续清晰分离。两类诉求可以同时满足：统一任务入口、进度读模型、异常卡和证据抽屉，各模块继续维护自己的真实状态。这个命题保留为需要真实老师对照验证的产品假设。

### 命题三：feature/use-case 拆分仍值得保留为阶段路线

通过 **S5 反面代价法**，三个核心文件已经达到 11376 行，历史累计新增约 11785 行、删除 409 行，`Exam.tsx` 有 32 次提交触达。持续追加会进一步提高定位、审查和并行施工成本。保留 R1.1—R5 的阶段路线，可以把增长逐步转成有边界的 feature、use-case 和任务读模型；每一阶段重新取证后再获得独立施工许可。

## 存活条件

### R1-A 成立条件

1. 只移动 `#[cfg(test)]` 测试模块，生产代码前缀保持字节级不变。
2. 测试名、断言、fixture、数量和私有可见性语义保持不变。
3. 目标 9 项、`module-exam` 208 项和 Tauri check 在改动后原样通过。
4. 工作区其他既有修改保持原样，不混入本批。
5. 目标 diff 经独立审查确认只改变测试组织。

任一条件未满足时，R1-A 不成立，文件行数下降不构成完成证据。

### 一站式产品假设成立条件

1. 统一的是老师任务入口和组合读模型，不复制模块事实。
2. 老师仍能回到原音频、原图、机器建议和人工决定。
3. 真实对照显示首次成功率提升，必要按钮数、异常定位时间或每百份主动操作时间下降。
4. 正常材料走直通路径，分歧、模糊和错位进入老师可处理的异常卡。

当统一入口必须改写领域事实，或真实对照没有形成可感知收益时，该产品假设不成立。

### 后续拆分路线成立条件

1. 每个阶段先拥有目标行为测试和独立执行合同。
2. 每批只改变一种结构因素。
3. facade、事务所有权、IPC、DTO 和审计语义保持稳定。
4. 每阶段用实际回执决定下一阶段是否获得许可。

## 概率量化

R1-A 属于确定性命题，采用二元闸门：五项验收全部成立记为通过，任一不成立记为未通过，不预先赋予成功百分比。

一站式产品价值属于非确定性命题，当前只适合宽区间先验：

| 存活条件 | 先验区间或档位 | 来源 |
|---|---|---|
| 任务壳可以在不合并领域事实的情况下实现 | 已验证架构条件 | Hegel、Bayes 与 R1 合同 |
| 统一入口能降低老师主动操作和定位时间 | 50%—75%，中等 | Debono 宽区间先验，尚无成对试点 |
| 收益不会被新增确认负担抵消 | 条件概率 60%—85%，中等 | 现有异常优先设计与老师访谈方向，尚无成对试点 |

两项非确定条件存在依赖，按条件概率计算：

`P(产品价值存活) = P(老师操作下降) × P(收益未被确认负担抵消 | 操作下降)`

当前宽区间约为 **30%—65%**。该区间只用于说明试点价值，不作为功能发布或代码施工门槛；真实老师对照数据到位后再更新。

## 四维价值扫描

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户价值 | 方向清晰、等待实测 | 老师最终获得一个任务、一个主动作和少量异常处理，而非理解多个技术模块 |
| 技术收益 | 立即可验证 | R1-A 降低生产文件阅读噪声，并建立合同驱动、单因素、可回归的重构范式 |
| 团队成长 | 可持续积累 | 把范围真相源、证据等级、失败停止条件和独立复审固化为后续施工习惯 |
| 战略对齐 | 高度一致 | 保留模块化单体、老师终审和本地证据链，同时为傻瓜式一站式体验逐步铺路 |

## 价值回溯结论

应保留的不是一次性“大重构”，而是两条互相支撑的主线：

1. 以 R1-A 建立可信施工能力；
2. 以真实老师任务指标逐步验证一站式产品体验。

R1.1—R5 继续作为候选路线存在，每阶段从上一个阶段的真实回执重新获得许可。
